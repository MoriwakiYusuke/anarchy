# Anarchy 開発状況レポート

> 対象読者: ソフトウェア開発経験者でブロックチェーン初学者

## 🎯 プロジェクト概要

**Anarchy** は、匿名分散型SNSを目指すブロックチェーンプロジェクトです。

従来のSNS（Twitter/X、Facebook等）との違い:
- **中央サーバーなし**: データは複数のノード（コンピュータ）に分散保存
- **検閲耐性**: 単一の管理者がコンテンツを削除できない
- **匿名性**: ユーザーの実世界の身元と投稿が紐付かない

---

## 🧱 ブロックチェーン基礎（これだけ押さえればOK）

### ブロックチェーンとは？

```
従来のDB:  [中央サーバー] ←→ クライアント
                ↓
           単一障害点、改ざん可能

ブロックチェーン: [ノードA] ↔ [ノードB] ↔ [ノードC] ...
                         ↓
               全員が同じデータを持つ、改ざん困難
```

### Substrate とは？

Polkadot（ポルカドット）エコシステムのブロックチェーン開発フレームワーク。
Ruby on Rails や Django のようなもの。

- **Rust製**: 安全性と高速性
- **モジュラー設計**: 機能を「パレット」という単位で追加
- **標準機能付属**: コンセンサス、P2P通信、ストレージなど

### パレット (Pallet) とは？

ブロックチェーンに機能を追加するプラグインのようなもの。
Node.jsのnpmパッケージ、PythonのPyPIパッケージに相当。

```
Anarchyのパレット構成:
├── pallet-moral  → トークン管理（残高、送金、発行）
├── pallet-post   → 投稿管理（作成、保存、取得）
└── pallet-faucet → PoW Faucet（匿名トークン配布）

※ Identity Pallet（WebAuthn検証）は設計見直しにより廃止
   → シンプルなAccountIdのみの認証に移行
```

## 🔢 トークンエコノミクス

### $moral トークン

- **精度**: 12桁（1 MORAL = 1,000,000,000,000 units）
- **用途**: 投稿のスパム防止コスト

### 投稿コスト計算

```
投稿コスト = 基本料金 + (バイト数 × バイト単価)
           = 10 MORAL + (bytes × 0.1 MORAL)

例:
- 空投稿(0bytes): 10 MORAL
- 100文字(300bytes): 10 + 30 = 40 MORAL
- 最大(10KB): 10 + 1000 = 1010 MORAL
```

### テストアカウント

開発環境では以下のアカウントに自動で10,000 MORALが付与:
- Alice, Bob, Charlie, Dave, Eve, Ferdie

## 🚀 起動方法

### 1. ブロックチェーンノード起動

```bash
cd apps/blockchain
./target/release/anarchy-node --dev --tmp
```

**オプション解説**:
- `--dev`: 開発モード（Alice単独でブロック生成）
- `--tmp`: 一時ディレクトリ使用（終了時にデータ削除）

**出力の見方**:
```
🏆 Imported #42     → ブロック#42をインポート（正常動作）
💤 Idle (0 peers)   → アイドル状態、ピア数0（--devでは正常）
🙌 Starting consensus → コンセンサス開始
```

### 2. フロントエンド起動

```bash
pnpm dev:frontend
# → http://localhost:3000
```

### 3. 動作確認

1. http://localhost:3000 を開く
2. 「Alice」でログイン（開発用アカウント）
3. 残高「10,000 MORAL」を確認
4. 投稿を作成 → タイムラインに表示
5. 残高が減少することを確認

## 🐛 既知の問題

### Runtime Constants アクセス問題

**症状**: フロントエンドから投稿コスト設定を取得できない

```
Error: Runtime entry Constant(Post.PostBaseCost) not found
```

**原因**: PAPI でのconstantsアクセス方法の調査中

**現在の対処**: フォールバック値（10 + 0.1×bytes）で動作

**影響**: 
- オンチェーン計算は正常（実際のコストは正しく課金）
- フロントエンド表示のみ固定値
