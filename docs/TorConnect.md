# Tor 接続パターンとハイドラ戦略

> **ステータス**: 設計ドキュメント  
> **関連ドキュメント**: [Tor.md](Tor.md), [architecture.md](architecture.md)

---

## 1. 概要

Anarchy における Tor 接続は、**「内部通信は直結、外部通信は Tor」** という原則に基づく。

> **「自分の家の中（Local）で仮面を被る必要はない。でも、一歩外（Remote）に出るなら、Tor という名のマントを羽織るのを忘れてはいけない。」**

---

## 2. 接続パターン

### 2.1 パターン一覧

| パターン | ユーザーの場所 | フロントの場所 | ノードの場所 | 推奨される接続 |
|---------|--------------|---------------|-------------|---------------|
| **開発/ソロ** | マシンA | マシンA | マシンA | `localhost` (直結) |
| **ハイドラ(頭)** | 世界中 | 公開サーバー | 隠しサーバー | `Frontend -> Tor -> Node` |
| **リモート操作** | マシンA | マシンA | 遠隔地 | `Local UI -> Tor -> Node` |

---

### 2.2 フルスタック・ノード型（全部入り）

```
┌─────────────────────────────────────────────┐
│                  マシンA                     │
│                                             │
│   ┌─────────────┐      ┌─────────────────┐  │
│   │  Next.js    │ ──── │  anarchy-node   │  │
│   │  localhost  │      │  localhost      │  │
│   └─────────────┘      └─────────────────┘  │
│                                             │
│         (Tor を通さず直結)                   │
└─────────────────────────────────────────────┘
```

**用途**: 開発環境、または自分のプライバシーを 100% 自分で守るコアユーザー

**メリット**:
- Tor のオーバーヘッド（遅延）がないため UI が爆速
- 通信が外部に出ないため漏洩リスクゼロ

**設定**:
```bash
anarchy-node \
  --rpc-cors all \
  --rpc-methods safe \
  --listen-addr /ip4/127.0.0.1/tcp/30333 \
  --rpc-port 9944
```

**結論**: **Tor を通さず localhost で繋ぐのが正解**

---

### 2.3 ハイドラ・ゲートウェイ型（一般公開）

```
┌──────────────┐              ┌──────────────┐              ┌──────────────┐
│    ユーザー   │   Clearnet   │   Next.js    │     Tor     │ anarchy-node │
│   ブラウザ    │ ──────────── │  フロント     │ ──────────── │   .onion     │
│              │   (HTTPS)    │  (公開IP)    │   (Hidden)   │              │
└──────────────┘              └──────────────┘              └──────────────┘
```

**用途**: 一般ユーザー向けの入り口（ゲートウェイ）

**メリット**:
- ユーザーは Tor Browser を使わずに普通のブラウザから参加可能
- 広い普及を狙える

**リスク**:
- フロントサーバーが「誰がアクセスしたか」という生 IP を知る
- サーバーが法的/物理的攻撃のターゲットになりやすい

**設定**:
```typescript
// Next.js API Routes で torsocks / http-proxy-agent を使用
import { SocksProxyAgent } from 'socks-proxy-agent';

const agent = new SocksProxyAgent('socks5h://127.0.0.1:9050');
const response = await fetch('http://your-node.onion:9944', { agent });
```

**結論**: **フロントサーバーが Tor クライアントとして動く必要がある**

---

### 2.4 カスタム・フロント型（セキュア接続）

```
┌──────────────────────────────────────────────────────────────────┐
│                          マシンA                                 │
│  ┌─────────────┐                               ┌──────────────┐  │
│  │  Next.js    │ ────── Tor ────────────────── │ リモートノード │  │
│  │  localhost  │        (SOCKS5)               │   .onion     │  │
│  └─────────────┘                               └──────────────┘  │
└──────────────────────────────────────────────────────────────────┘
```

**用途**: UI は自分の好きなものを使いたいが、ノードは信頼できる友達のノードや公式シードノードを使いたい場合

**メリット**:
- ノードを自分で立てるリソース（CPU/Disk）がなくても通信経路だけは匿名化可能
- 自分の IP が相手ノードに漏れない

**設定**:
```bash
# ブラウザのプロキシ設定を Tor に向ける
export ALL_PROXY=socks5h://127.0.0.1:9050

# または環境変数で設定
NEXT_PUBLIC_RPC_ENDPOINT=socks5h://127.0.0.1:9050/your-node.onion:9944
```

**結論**: **UI が直接 Tor ネットワークへダイブする構成**

## 3. ハイドラ・ゲートウェイの 2 形態

「ハイドラの頭」には **「表向きの顔」** と **「隠れた顔」** の 2 種類がある。

### 3.1 比較表

| 特徴 | **A. Clearnet Gateway** | **B. Onion Gateway** |
|------|------------------------|---------------------|
| **URL** | `https://anarchy-social.com` | `http://anarchy7...onion` |
| **対象** | 一般ユーザー, モバイル, 検索エンジン | 匿名希望者, 検閲地域, ジャーナリスト |
| **入口の匿名性** | **低い** (サーバーはユーザーの生IPを知る) | **高い** (サーバーもユーザーも匿名) |
| **レジリエンス** | **中** (ドメイン没収やIP遮断に弱い) | **最強** (場所が特定できず, 遮断も困難) |
| **SSL/TLS** | 必須 (Let's Encrypt 等) | 不要 (Onion 自体が暗号化されている) |

---

### 3.2 Clearnet Gateway（一般IP公開型）

「普通のウェブサイト」として振る舞う頭。

```
インターネット
     │
     │ HTTPS (443)
     ▼
┌─────────────────────────────────────┐
│  Clearnet Gateway                    │
│  (AWS / Vercel / VPS)                │
│                                      │
│  Public IP: 203.0.113.50             │
│  Domain: anarchy-social.com          │
│                                      │
│  ┌──────────────┐   ┌─────────────┐  │
│  │   Next.js    │───│   torsocks  │──┼──── Tor ──── .onion Node
│  └──────────────┘   └─────────────┘  │
└─────────────────────────────────────┘
```

**役割**: Anarchy の思想を一般層に広めるための「窓口」

**仕組み**:
- サーバーは普通のクラウド（AWS, Vercel 等）に配置
- ユーザーは HTTPS で接続
- サーバーの裏側で `torsocks` を使い、Tor ネットワーク内のノードへ通信を中継

**弱点**:
- サーバーの IP が公開されているため、法的な差し押さえや DDoS 攻撃のターゲットになる

---

### 3.3 Onion Gateway（Tor公開型）

「ダークウェブ内のポータル」として機能する頭。

```
Tor Network
     │
     │ Onion Service
     ▼
┌─────────────────────────────────────┐
│  Onion Gateway                       │
│  (物理的場所: 不明)                    │
│                                      │
│  Public IP: なし                      │
│  Address: anarchy7xyz...onion         │
│                                      │
│  ┌──────────────┐                    │
│  │   Next.js    │────────────────────┼──── localhost ──── anarchy-node
│  └──────────────┘                    │
└─────────────────────────────────────┘
```

**役割**: Clearnet 側が全て焼き払われても生き残る「最後の砦」

**仕組み**:
- フロントエンド（Next.js）自体を Tor の Onion Service としてホスト
- サーバー自体にパブリック IP を持たせる必要がない
- 完全に「霧の中」で運営可能

**強み**:
- サーバーの物理的な場所を特定するのが極めて困難
- 物理的な差し押さえに対して無敵に近い耐性

## 4. なぜ両方必要なのか？

### 4.1 戦略的合理性

```
┌─────────────────────────────────────────────────────────────────┐
│                      ハイドラ戦略                                │
│                                                                 │
│   ┌─────────────────┐              ┌─────────────────┐          │
│   │  Clearnet 頭    │              │   Onion 頭      │          │
│   │  (光の部分)     │              │  (影の部分)     │          │
│   │                 │              │                 │          │
│   │  ・一般人を集客  │              │  ・自由を守る    │          │
│   │  ・検索可能      │              │  ・検閲耐性      │          │
│   │  ・モバイル対応  │              │  ・最後の砦      │          │
│   └────────┬────────┘              └────────┬────────┘          │
│            │                                │                   │
│            └────────────┬───────────────────┘                   │
│                         │                                       │
│                         ▼                                       │
│              ┌─────────────────────┐                            │
│              │   ブロックチェーン    │                            │
│              │   (真の本体)         │                            │
│              └─────────────────────┘                            │
└─────────────────────────────────────────────────────────────────┘
```

1. **段階的な避難**: `anarchy-social.com` が消されたら、ユーザーはブックマークしていた `.onion` アドレスへ移動
2. **アクセスの民主化**: Tor Browser を入れるのが面倒な一般人は Clearnet 型を使い、命がけの告発をするジャーナリストは Onion 型を使う
3. **相互監視**: 複数の Onion ゲートウェイが存在することで、特定の Clearnet ゲートウェイが「検閲」をしていないかユーザーが答え合わせ可能

## 5. 実装ガイド

### 5.1 環境変数による切り替え

同じコードベースで、環境変数一つで Clearnet 用か Onion 用かを切り替え可能にする：

```typescript
// lib/config.ts
export const config = {
  // RPC エンドポイント
  rpcEndpoint: process.env.NEXT_PUBLIC_RPC_ENDPOINT || 'ws://127.0.0.1:9944',
  
  // Tor プロキシ (Onion モード時)
  torProxy: process.env.TOR_PROXY || 'socks5h://127.0.0.1:9050',
  
  // ゲートウェイモード
  gatewayMode: process.env.GATEWAY_MODE as 'local' | 'clearnet' | 'onion' || 'local',
};
```

### 5.2 Docker Compose 構成例

```yaml
# docker-compose.yml
version: '3.8'

services:
  # Clearnet Gateway
  frontend-clearnet:
    build: ./apps/frontend
    ports:
      - "3000:3000"
    environment:
      - GATEWAY_MODE=clearnet
      - TOR_PROXY=socks5h://tor:9050
      - NEXT_PUBLIC_RPC_ENDPOINT=http://node.onion:9944
    depends_on:
      - tor

  # Onion Gateway
  frontend-onion:
    build: ./apps/frontend
    environment:
      - GATEWAY_MODE=onion
      - NEXT_PUBLIC_RPC_ENDPOINT=ws://node:9944
    depends_on:
      - node

  # Tor Service
  tor:
    image: dperson/torproxy
    ports:
      - "9050:9050"
    volumes:
      - ./torrc:/etc/tor/torrc

  # Blockchain Node
  node:
    build: ./apps/blockchain
    command: >
      --chain local
      --listen-addr /ip4/127.0.0.1/tcp/30333
      --rpc-cors all
```
