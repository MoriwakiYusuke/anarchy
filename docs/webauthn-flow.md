# WebAuthn パスキー登録フロー

## 概要

Anarchyでは、従来のウォレット秘密鍵管理ではなく、**WebAuthn（パスキー）** を使用してユーザー認証を行います。

### 鍵の管理

| 場所 | 保管するもの |
|------|------------|
| **ユーザーのデバイス** | 秘密鍵（パスキー内、外部に出ない） |
| **ブロックチェーン** | 公開鍵（COSE形式） |

### 基本フロー

1. **アカウント作成**: デバイスで秘密鍵/公開鍵ペアを生成 → 公開鍵をチェーンに登録
2. **投稿時**: デバイス内で秘密鍵を使って署名 → 署名をチェーンで検証

※ 秘密鍵はデバイスのセキュアエンクレーブに保管され、生体認証なしでは使用できません。

## 詳細フロー

### 1. 新規パスキー登録（register_identity）

```
ユーザー操作                  フロントエンド                    ブロックチェーン
    │                            │                                 │
    │ 「パスキーを追加」クリック    │                                 │
    │───────────────────────────>│                                 │
    │                            │                                 │
    │                            │ navigator.credentials.create()  │
    │                            │──────────────┐                  │
    │                            │              │                  │
    │<─────────────────────────────────────────┘                  │
    │ 生体認証を要求              │                                 │
    │                            │                                 │
    │ 指紋/顔認証実行             │                                 │
    │───────────────────────────>│                                 │
    │                            │                                 │
    │                            │ デバイス内部:                    │
    │                            │ ┌─────────────────────────────┐│
    │                            │ │ 1. 秘密鍵/公開鍵ペアを生成   ││
    │                            │ │ 2. 秘密鍵をセキュア領域に保存 ││
    │                            │ │ 3. 公開鍵(COSE形式)を返却    ││
    │                            │ └─────────────────────────────┘│
    │                            │                                 │
    │                            │ 公開鍵をチェーンに登録           │
    │                            │ Identity.register_identity()    │
    │                            │────────────────────────────────>│
    │                            │                                 │
    │                            │                                 │ 1. Identity ID発行
    │                            │                                 │ 2. 公開鍵を保存

    │                            │ IdentityCreated イベント          │
    │                            │                                 │
    │                            │ LocalStorageに保存:              │
    │                            │ - identityId                    │
```

**ポイント**: 秘密鍵はデバイスから外に出ない。公開鍵のみがチェーンに登録される。

### 2. 署名付き投稿（create_post_with_webauthn）

```
ユーザー操作                  フロントエンド                    ブロックチェーン
    │                            │                                 │
    │ 投稿内容入力                │                                 │

    │                            │ 2. WYSIWYSチャレンジ生成:        │
    │                            │    "anarchy:post:" + hash       │
    │                            │                                 │
    │                            │ navigator.credentials.get()      │
    │                            │──────────────┐                  │
    │                            │              │                  │
    │<─────────────────────────────────────────┘                  │
    │ 生体認証を要求              │                                 │
    │                            │                                 │
    │ 指紋/顔認証実行             │                                 │
    │───────────────────────────>│                                 │
    │                            │                                 │
    │                            │ デバイス内部:                    │
    │                            │ ┌─────────────────────────────┐│
    │                            │ │ 1. 秘密鍵でチャレンジに署名   ││
    │                            │ │ 2. 署名結果を返却            ││
    │                            │ │ (秘密鍵は外に出ない)          ││
    │                            │ └─────────────────────────────┘│
    │                            │                                 │
    │                            │ 署名データをチェーンに送信       │
    │                            │ Post.create_post_with_webauthn() │
    │                            │────────────────────────────────>│
    │                            │                                 │
    │                            │                                 │ 1. Identityを検索
    │                            │                                 │ 2. 保存済み公開鍵を取得
    │                            │                                 │ 3. 公開鍵で署名を検証
    │                            │                                 │ 4. WYSIWYS検証
    │                            │                                 │ 5. MORALを消費
    │                            │                                 │ 6. 投稿保存
    │                            │                                 │
    │                            │<────────────────────────────────│
    │                            │ PostCreated イベント              │
    │                            │                                 │
    │<───────────────────────────│                                 │
    │ 投稿完了！                   │                                 │
```

**ポイント**: 署名はデバイス内部で行われ、署名結果のみがチェーンに送られる。チェーンは保存済みの公開鍵で検証する。

## データの永続化

### LocalStorage

ブラウザのLocalStorageに以下のデータを保存：

| キー | 内容 |
|------|------|
| `anarchy_webauthn_identity` | 現在アクティブなIdentity情報 |
| `anarchy_webauthn_credentials` | 登録済みパスキーの一覧 |

```typescript
// StoredIdentity 構造
{
  identityId: "123",          // チェーン上のIdentity ID
  passkeyId: "base64...",     // パスキーID (Blake2-256)
  credentialId: "base64...",  // WebAuthn credential ID
  deviceName: "MacBook Pro",  // デバイス名（オプション）
  lastUsed: 1707393600000     // 最終使用時刻
}
```

### ブロックチェーン（pallet_identity）

| ストレージ | 内容 |
|-----------|------|
| `Identities` | Identity ID → Identity データ |
| `PasskeyOwner` | Passkey ID → Identity ID |
| `NextIdentityId` | 次のIdentity ID |

```rust
// Identity 構造
Identity {
  created_at: BlockNumber,
  passkeys: Vec<Passkey>,  // 最大8個
}

// Passkey 構造
Passkey {
  id: [u8; 32],            // Blake2-256(public_key)
  public_key: Vec<u8>,     // COSE形式の公開鍵
  registered_at: BlockNumber,
  last_used_at: BlockNumber,
  device_name: Option<Vec<u8>>,
}
```

## エラーケースと対処法

### 「指定されたIdentityが見つかりません」

**原因**: LocalStorageにIdentity情報があるが、チェーン上にそのIdentityが存在しない

**よくある原因**:
- `--dev` モードでノードを再起動し、チェーンデータがリセットされた
- 別のチェーンに接続している

**対処法**:
1. ブラウザのLocalStorageをクリア
   - DevTools → Application → Local Storage → `http://localhost:3000` → 削除
2. または、アプリ内の「ログアウト」ボタン（実装予定）

### 「MORAL残高が不足しています」

**原因**: 投稿にはMORALトークンが必要

**対処法**:
```bash
# 開発環境でAliceにMORALをmint
cd apps/frontend
node mint-moral.mjs Alice 1000000
```

### 「トランザクションが失敗しました」

**原因**: ブロックチェーンノードが起動していない、または接続エラー

**対処法**:
```bash
# ノードを起動
cd apps/blockchain
cargo run --release -- --dev
```

## 開発時の注意点

### チェーンリセット時

`--dev` モードでノードを再起動すると、チェーンデータは完全にリセットされます。
その際、ブラウザのLocalStorageも手動でクリアする必要があります。

```javascript
// DevTools Console で実行
localStorage.removeItem('anarchy_webauthn_identity')
localStorage.removeItem('anarchy_webauthn_credentials')
```

### 複数デバイス対応

1つのIdentityに最大8個のパスキーを登録できます。
別のデバイスからパスキーを追加するには `Identity.add_passkey` を使用します。

| アクション | MORALコスト |
|-----------|------------|
| Identity登録 | 無料 |

## 参考: WYSIWYS (What You See Is What You Sign)

パスキーで署名する際、ユーザーが見ている内容と署名する内容が一致していることを保証します。

```
チャレンジ = "anarchy:post:" + SHA-256(投稿内容) + ":end"
```

1. フロントエンドが投稿内容のハッシュを含むチャレンジを生成
2. デバイスがそのチャレンジに対して**秘密鍵で署名**
3. チェーンが**公開鍵で署名を検証**し、投稿内容の改ざんを防止

## 暗号方式

| 項目 | 値 |
|------|-----|
| 署名アルゴリズム | ECDSA P-256 (ES256) |
| 公開鍵形式 | COSE (RFC 8152) |
| ハッシュ | SHA-256 (チャレンジ), Blake2-256 (Passkey ID) |
