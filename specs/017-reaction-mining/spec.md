# Feature Specification: Reaction Mining

**Feature Branch**: `017-reaction-mining`  
**Created**: 2026-02-28  
**Status**: Implemented  
**Last Updated**: 2026-03-01  
**Input**: User description: "反応マイニング機能 - PoWベースの反応（いいね、ブースト等）と投稿者報酬システム"

## 概要

ユーザーが投稿に対して反応（いいね、ブースト）を行う際、クライアント側でProof-of-Work（PoW）計算を行い、その計算コストに応じて投稿者に$moral報酬を付与するシステム。スパム防止とクリエイター報酬を同時に実現する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 投稿への反応 (Priority: P1)

ユーザーが気に入った投稿に「いいね」や「ブースト」で反応できる。反応時にはクライアント側でPoWマイニングが実行され、完了後に反応がオンチェーンに記録される。投稿者は反応に応じた$moral報酬を受け取る。

**Why this priority**: 反応機能はSNSの根幹であり、この機能がなければクリエイターへの報酬システムが成立しない。最も基本的かつ重要な機能。

**Independent Test**: 投稿を表示し、いいねボタンを押してPoWが完了するまで待ち、投稿者の残高が増加することを確認する。

**Acceptance Scenarios**:

1. **Given** ユーザーAが投稿を閲覧している, **When** いいねボタンを押す, **Then** マイニング進捗UIが表示され、完了後に反応が記録される
2. **Given** マイニングが完了した, **When** 反応がオンチェーンに記録される, **Then** 投稿者に$moral報酬が自動付与される
3. **Given** ユーザーが既に同じ投稿に反応済み, **When** 再度反応しようとする, **Then** 二重反応として拒否される

---

### User Story 2 - フォアグラウンド強制マイニング (Priority: P1)

マイニングはアプリがフォアグラウンドにある時のみ実行される。バックグラウンドに移行した場合、マイニングは一時停止し、フォアグラウンドに戻ると再開する。

**Why this priority**: Botやバックグラウンド悪用によるスパム反応を防止するため必須。ユーザーの意図的な参加を保証する。

**Independent Test**: マイニング中にブラウザタブを切り替え、マイニングが停止することを確認。タブに戻ると再開することを確認。

**Acceptance Scenarios**:

1. **Given** マイニング実行中, **When** ユーザーがタブを切り替える, **Then** マイニングが一時停止する
2. **Given** マイニングが一時停止中, **When** ユーザーがタブに戻る, **Then** マイニングが自動再開する
3. **Given** ブラウザがバックグラウンドで長時間経過, **When** フォアグラウンドに戻る, **Then** 安全にマイニングを再開できる

---

### User Story 3 - 動的難易度調整 (Priority: P2)

ネットワーク全体の反応レートに基づいて、PoW難易度が自動調整される。反応が多すぎる場合は難易度が上がり、少なすぎる場合は下がる。

**Why this priority**: インフレ/デフレを防ぎ、持続可能な報酬システムを維持するために重要。ただしMVPではハードコード難易度でも動作可能。

**Independent Test**: テストネットで大量の反応を発生させ、難易度パラメータが変化することを確認。

**Acceptance Scenarios**:

1. **Given** 直近の反応レートが目標を超過, **When** 次のブロックが生成される, **Then** 難易度が上昇する
2. **Given** 直近の反応レートが目標を下回る, **When** 次のブロックが生成される, **Then** 難易度が低下する
3. **Given** 難易度が最大/最小値に達している, **When** さらに調整が必要な状況, **Then** 上限/下限で制限される

---

### User Story 4 - ステルスアドレス報酬先 (Priority: P3)

ユーザーは反応時に報酬の受取先としてステルスアドレスを指定できる。これにより、反応者と報酬受取口座の紐付けを防ぎ、プライバシーを保護する。

**Why this priority**: プライバシー強化機能。基本機能が動作した後の拡張として実装。

**Independent Test**: ステルスアドレスを生成し、そのアドレスを報酬先に指定して反応。報酬がステルスアドレスに届くことを確認。

**Acceptance Scenarios**:

1. **Given** ユーザーがステルスアドレスを生成済み, **When** 反応時に報酬先として指定, **Then** 報酬がステルスアドレスに送付される
2. **Given** 報酬先が指定されていない, **When** 反応する, **Then** デフォルトで投稿者のメインアカウントに報酬が送付される

---

### Edge Cases

- PoWチャレンジの有効期限が切れた場合、再計算が必要
- マイニング中にネットワーク接続が切れた場合の回復処理
- 同一投稿に複数ユーザーが同時に反応した場合の並行処理
- 投稿者アカウントが削除/無効化された場合の報酬処理
- 極端に短い時間でPoWが解けた場合の不正検出

## Requirements *(mandatory)*

### Functional Requirements

#### Reaction Pallet（チェーン側）

- **FR-101**: システムは反応種別（Like, Boost, Bad）を定義し、投稿ごとに記録できること
- **FR-102**: システムは投稿への反応をオンチェーンに永続化できること
- **FR-103**: システムは同一ユーザーによる同一投稿への二重反応を防止すること
- **FR-104**: システムは反応時にPoW証明を検証し、難易度要件を満たさない場合は拒否すること
- **FR-105**: システムは有効な反応に対して投稿者に$moral報酬を自動付与すること（Badは報酬なし）
- **FR-106**: 報酬は固定1 MORAL/反応（Like/Boost共通、Bad=0）
- **FR-107**: システムは投稿ごとの反応数をクエリ可能にすること
- **FR-108**: システムはユーザーごとの反応履歴をクエリ可能にすること
- **FR-109**: 報酬はReactionRewardPoolから支払われること（プール残高分mintして投稿者へ）
- **FR-110**: 報酬プール残高が不足する場合、反応は記録されるが報酬は支払われないこと
- **FR-111**: 反応報酬プールにはジェネシスで初期ミントを行うこと（10,000,000 MORAL）
- **FR-112**: PoWチャレンジの有効期限は100ブロック（約10分）とすること

#### クライアント側PoW

- **FR-201**: クライアントはWebWorker内でPoWマイニングを実行すること
- **FR-202**: マイニングはPage Visibility APIによりフォアグラウンド時のみ実行されること
- **FR-203**: クライアントはチェーンから現在の難易度パラメータを取得できること
- **FR-204**: クライアントはマイニング進捗（ハッシュレート、推定残り時間）をUIに表示すること
- **FR-205**: マイニングはユーザーによるキャンセルが可能であること

#### 動的難易度調整

- **FR-301**: システムはネットワーク全体の反応レートを監視すること
- **FR-302**: システムは目標反応レートに基づいて難易度を自動調整すること
- **FR-303**: 難易度には上限・下限が設定されること
- **FR-304**: インフレ/デフレ抑制のため、報酬係数γを総供給量に応じて調整すること

#### ステルスアドレス対応

- **FR-401**: ユーザーは反応時に報酬受取先としてステルスアドレスを指定できること
- **FR-402**: 報酬先が未指定の場合、投稿者のメインアカウントに報酬が送付されること

### Key Entities

- **Reaction**: 投稿への反応。反応者、反応種別、PoW証明、計算パワー、作成日時を持つ
- **ReactionType**: 反応の種類（Like = いいね, Boost = 拡散, Bad = 低品質報告）
- **PostReactions**: 投稿IDから反応リストへのマッピング
- **UserReactions**: (ユーザーID, 投稿ID)から反応有無へのマッピング（二重反応防止用）
- **ReactionCounts**: 投稿IDから反応種別ごとの反応数へのマッピング（高速カウント取得用）
- **BadCounts**: 投稿IDからBad反応数へのマッピング（将来のストレージ削除判定用）
- **DifficultyState**: 現在の難易度、反応履歴、調整パラメータ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ユーザーは30秒以内に投稿への反応を完了できる（標準難易度時）
- **SC-002**: システムは1ブロックあたり100件以上の反応を処理できる
- **SC-003**: 投稿者は反応から1ブロック以内に報酬を受け取る
- **SC-004**: フォアグラウンド強制により、バックグラウンドBot反応は0%に抑制される
- **SC-005**: 難易度調整により、反応レートは目標値の±20%以内に維持される
- **SC-006**: 二重反応防止により、同一ユーザーの重複反応は100%ブロックされる

## Assumptions

- pallet-faucetの既存PoW検証ロジックを流用可能
- pallets/stealthが存在し、ステルスアドレス生成・検証が可能
- フロントエンドのWebWorker基盤（WorkerPool.ts, crypto.ts）が既存
- $moralトークンの12桁精度はそのまま適用

## Implementation Notes (2026-03-01)

### 完成した実装

#### チェーン側 (pallet-reaction)

- **ストレージ**: Reactions, ReactionStatsStorage, ReactionRewardPool, CurrentDifficulty, ReactionHistory
- **エクストリンシック**: `react(post_id, reaction_type, block_number, nonce, cpu_power, stealth_recipient)`
- **報酬フロー**: 
  - Like/Boost時、ReactionRewardPool残高を確認
  - 残高 >= 1 MORAL ならプールから1 MORAL差し引いて投稿者にmint
  - 残高不足時は報酬なし（反応自体は記録）
- **PostAuthorProvider**: pallet-postから投稿者を取得するtrait
- **難易度**: 16ビット（faucetの18ビットより簡単）
- **動的難易度調整**: on_finalizeフックでAdjustmentWindowブロックごとに自動調整
- **テスト**: 18テスト全てpass

#### フロントエンド側

- **ReactionButton.tsx**: X風のハート/リツイート/Badボタン
- **useReactionMining.ts**: PoWマイニングフック
- **miningWorker.ts**: WebWorkerでのBlake2bマイニング
- **reactionService.ts**: チェーンインタラクション
- **UI機能**:
  - マイニング進捗表示（ハッシュレート、経過時間）
  - エラー表示（すでに反応済み、接続してください）
  - 反応数表示（Timelineから取得）
  - 投稿ごとに1回のみ反応可能

### 未実装

- 投稿手数料から報酬プールへの自動補充
